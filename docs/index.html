Arcana does not trust file names: it reads the first bytes and looks for the signature of each format. This page applies the same detection rules to the first bytes of your file, in your browser. Overview

      
Arcana is a single JAR that is both a command-line tool and a Java library. It reads the archive formats you meet in practice, writes the most common ones, and tells you what an unknown file is.

      
Everything is implemented in Java: the decompressors (Deflate, Deflate64, LZMA, LZMA2, PPMd, BZip2, LZ4, Zstandard, Brotli, LZX, the RAR 4 and RAR 5 algorithms...), the encryption (AES, ZipCrypto) and the container formats. There is no call to a native library and no third-party JAR, so Arcana behaves the same on Windows, Linux and macOS and can be dropped into any Java 8 application.

      
What you can do with it

      

        
Extract

        
every supported format, encrypted or not, from a file or from a stream.

        
Compress

        
to ZIP, 7z, TAR (plain, GZIP, BZIP2, XZ, LZ4), GZIP, BZIP2, XZ, LHA and CAB, with AES-256 encryption for ZIP and 7z.

        
Identify

        
any file: archive, executable, image, document, database, font, media, with its version and details.

        
Recover

        
what is still readable in a damaged archive, with a report giving the state of every file.

        
Split

        
files made of several files glued together, such as installers and self-extracting archives.

        
Extend

        
with plugins that add formats without changing Arcana.

Command line


java -jar Arcana-v1.0.0.jar <command> [options]

      
In the examples below, arcana stands for java -jar Arcana-v1.0.0.jar. On Windows, a one-line arcana.bat next to the JAR gives you the short form: @java -jar "%~dp0Arcana-v1.0.0.jar" %*.

      
Run it without arguments for the syntax of each command, and with help (or -h, --help) for the descriptions, options and examples. version (or -v, --version) prints the version.


      

        
arcana x <archive> [-o dest] [-p password] [-f format]

        
Extracts the archive into dest, or into the current directory.

        
arcana l <archive> [-p password] [-f format]

        
Lists the contents: size, date and name of every entry.

        
arcana c <source> <archive> [-t format] [-l 0-9] [-p password]

        
Compresses a file or a directory. The format comes from the archive name, using the longest known extension (backup.tar.gz gives tar.gz); -t sets it explicitly.

        
arcana r <archive> [-o dest] [-p password] [-f format]

        
Recovers a damaged archive: extracts everything that can still be read and writes a report.

        
arcana s <file> [-o dest] [-n]

        
Splits a file made of files glued together into dest/file name/.

        
arcana i <file>

        
Identifies a file: category, type, version and details.

        
arcana formats [extract|compress]

        
Lists the supported formats, optionally only those that can be extracted or created.

        
arcana plugins [<file>]

        
Lists the plugins found, loaded or refused, with their directories and checksums. With a file, shows which plugin or format Arcana chooses for it, and why.

Options

      

        

          
OptionCommandsMeaning

          
            
-o <dir>x, r, sOutput directory. It can also be given as the second argument: arcana x a.zip out.

            
-p <password>x, l, r, cPassword to decrypt; with c, encrypts the new ZIP or 7z archive with AES-256.

            
-f <format>x, l, rForces the input format instead of detecting it: a format name or extension (zip, tar.gz...), or a plugin id.

            
-t <format>cForces the output format instead of taking it from the archive name.

            
-l <level>c0 (fastest) to 9 (smallest) for 7z, xz and tar.xz, default 6; 5, 6 or 7 for lzh (-lh5-, -lh6-, -lh7-).

            
-nsLists the pieces without writing anything.

          
        

      

      
Before running any command, Arcana prints on the error output the plugins it refused, with the reason, or [plugins] No plugin found in any plugin directory. when there is none. Nothing is printed when every plugin loaded correctly. Because these lines go to the error output, they do not mix with a listing you redirect to a file.


      
Damaged archives

      
Normal extraction stops at the first error, so that you never get a damaged file without knowing it. arcana r does the opposite: it keeps everything that can be read and gives the state of every file.


$ arcana x photos.zip
Extracting photos.zip -> /home/anna
Error: ZIP entry 'photos/sunset.png' has 2 bytes instead of 2366
$ arcana r photos.zip -o rescue
Archive : photos.zip
Method  : ZIP: local headers scanned one by one
Result  : 3 file(s): 2 OK, 0 unverified, 1 bad checksum, 0 partial, 0 lost

Status            Written / Expected     Name
OK                     14 / 14           docs/notes.txt
OK                     12 / 12           docs/budget.csv
BAD_CHECKSUM            2 / 2366         photos/sunset.png  (CRC c0f36009 instead of 364d29a8)

Report written to /home/anna/rescue/_ARCANA_RECOVERY_REPORT.txt

      

        

          
StatusMeaning

          
            
OKDecoded completely, and its checksum (when the format has one) is correct.

            
UNVERIFIEDDecoded completely, but no checksum could confirm the content.

            
BAD_CHECKSUMDecoded completely, but the checksum does not match: the content is damaged.

            
PARTIALDecoding stopped on an error: only the beginning of the file was written.

            
LOSTNothing could be decoded (encrypted, unsupported method, destroyed data).

          
        

      

      
A recovered file can be incomplete or contain garbage. Check every file whose status is not OK before using it.


      
Glued files

      
Installers, self-extracting archives and firmware images are often several files placed one after the other. arcana s finds where each one starts and ends.


$ arcana s bundle.bin -n
  Offset         Size  Type     Description
  0x00000000        99840  pe       PE32+ EXE x64
  0x00018600          452  7z       7-Zip archive
  0x000187C4         2366  png      PNG image
  3 piece(s), 3 recognized

      
Without -n, the pieces are written into bundle/ in the output directory, named after their position and type (001_0x00018600.7z...). Parts that match no known format are written too, with _unknown in their name, so nothing is lost; only gaps made of zero bytes are skipped.

Java API

      
Add the JAR to your class path. The entry point is be.stef.arcana.Arcana.


import be.stef.arcana.Arcana;
import be.stef.arcana.ArcanaEntry;
import be.stef.arcana.ArcanaFormat;

// Format detected from the content
Arcana.extractTo(new File("archive.tar.gz"), new File("out"));

// Entries, without extracting
for (ArcanaEntry e : Arcana.listEntries(new File("archive.rar"))) {
    System.out.println(e.getName() + "  " + e.getUncompressedSize());
}

// Encrypted archive
Arcana.withPassword("secret".getBytes("UTF-8")).extract(new File("secure.7z"), new File("out"));

// From a stream: the format must be given
try (InputStream in = new FileInputStream("data.bz2")) {
    Arcana.with(ArcanaFormat.BZIP2).extract(in, new File("out"));
}

      
ArcanaEntry also gives the compressed size, the modification time and whether the entry is a directory.


      
Compression


import be.stef.arcana.compressor.ZipCompressor;
import be.stef.arcana.plugin.FormatRegistry;

byte[] password = "secret".getBytes("UTF-8");

new ZipCompressor().compress(new File("mydir"), new File("backup.zip"));
new ZipCompressor(password).compress(new File("mydir"), new File("secure.zip"));   // WinZip AES-256
new ZipCompressor(password, ZipCompressor.ENCRYPT_ZIPCRYPTO).compress(new File("mydir"), new File("legacy.zip"));

// Any format: level 0-9 (-1 = default), password or null
FormatRegistry.builtin(ArcanaFormat.SEVEN_Z).createCompressor(9, password).compress(new File("mydir"), new File("vault.7z"));
FormatRegistry.builtin(ArcanaFormat.TAR_XZ).createCompressor(-1, null).compress(new File("mydir"), new File("backup.tar.xz"));

      
createCompressor returns null for a format Arcana can only extract. ZipCrypto is weak encryption: use it only when the archive must open in very old tools.

import be.stef.arcana.analyze.Identification;

}

Recovery


import be.stef.arcana.formats.recover.RecoveryReport;

RecoveryReport report = Arcana.forceUnpack(new File("damaged.zip"), new File("rescue"));
System.out.println(report.summary());
for (RecoveryReport.Entry e : report.getEntries()) {
    if (e.status != RecoveryReport.Status.OK) System.out.println(e.name + ": " + e.status);
}

      
The same report is written to _ARCANA_RECOVERY_REPORT.txt in the destination directory.


      
Extraction limits

      
Every extraction made through Arcana is guarded by the limits of be.stef.arcana.util.ExtractionLimits. They are public static fields that you can change at run time.

      

        

          
FieldDefaultEffect

          
            
maxRatio1000Largest allowed ratio between the extracted size and the archive size, checked once ratioThreshold bytes are written. Stops decompression bombs.

            
ratioThreshold1 GiBExtracted size from which the ratio is checked.

            
maxTotalBytes0 (no limit)Largest total size one extraction may write.

            
minFreeSpace256 MiBThe extraction stops before the disk has less free space than this.

Plugins

      
A plugin is a JAR that adds a format to Arcana: extraction, and if the format allows it, creation, recovery, detection inside glued files or identification. Once installed, its format works with every command and through the Java API, exactly like a built-in one.

      
Installing a plugin

      
Copy the JAR into one of these directories, then check with arcana plugins:

      
    
        
  • plugins/ next to the Arcana JAR;
    • 
        
  • .arcana/plugins/ in your home directory;
    • 
        
  • plugins/ in the current directory.
    • 
      

      
The system property arcana.plugins.dir replaces these directories with your own list, separated by the path separator: java -Darcana.plugins.dir=D:\tools\arcana-plugins -jar Arcana-v1.0.0.jar ...

Rules checked at load time

      
A plugin JAR is refused, with the reason printed on every run, unless:

      
    
        
  • the JAR contains the source code of each of its classes, so that anyone can read what it does;
    • 
        
  • it declares a source URL and a license;
    • 
        
  • its id is not already used by another plugin;
    • 
        
  • its classes use their own package: be.stef.arcana is reserved for Arcana;
    • 
        
  • it declares its plugin class in META-INF/services/be.stef.arcana.plugin.ArcanaPlugin.
    • 
      

      
Which format wins

      
For each file, Arcana looks in this order and takes the first match:

      
    
        
  1. plugins with a priority above 0, highest first (they can replace a built-in format, on purpose);
    2. 
        
  2. the built-in formats recognized by their content;
    3. 
        
  3. the other plugins, in load order;
    4. 
        
  4. the built-in formats recognized by their extension, then the search for an archive inside an executable.
    5. 
      

      
A plugin with the default priority can therefore never take a file away from a built-in format. arcana plugins <file> shows the decision for a given file.


      
Plugins from Java

      
Your application can use plugins in three ways. In each case, the extraction goes through Arcana, so the extraction limits apply.


// 1. Plugin JAR in a plugin directory: detection works as for any archive
System.setProperty("arcana.plugins.dir", "D:/myapp/plugins");   // optional, before the first use of Arcana
Arcana.extractTo(new File("setup.exe"), new File("out"));               // writes out/setup.unpacked.exe

// 2. Force a plugin, by id or by extension
Arcana.withPlugin("io.github.realburst.upx", null).extract(new File("setup.exe"), new File("out"));
Arcana.withPlugin("pak", null).extract(new File("pak0.pak"), new File("out"));

// 3. Plugin JAR on the class path of your application: found automatically,
//    or registered by code (no source check: you chose your dependencies)
PluginManager.get().register(new MyPlugin());

// Loaded and refused plugins
for (PluginManager.PluginInfo info : PluginManager.get().getPlugins()) System.out.println(info);

      
Plugins are loaded once, at the first use of Arcana: set arcana.plugins.dir before that.


      
Known plugins

      

        
A plugin is ordinary Java code that runs with the same rights as Arcana and your application. Being listed here is not a security audit. Read the source of a plugin before installing it, download it only from its own repository, and check that the SHA-256 shown by arcana plugins matches the published one.

      

      

        

          
PluginWhat it doesFilesCapabilitiesAuthorLicense

          
            
The list of known plugins is in plugins.json.

          
        

      

      
To have your plugin listed, open an issue titled Plugin: <name> with its name, the URL of its public repository, its id, a one-sentence description, the formats it handles, its capabilities, its author and license, the Arcana version it was tested with, and the link and SHA-256 of its JAR. The plugin stays in your repository and under your control.


      
Write a plugin

      
Implement be.stef.arcana.plugin.ArcanaPlugin (and an ArchiveExtractor), declare it in META-INF/services, and package the classes together with their sources. The complete guide, with a working example, is in PLUGIN-API.md.


public final class FooPlugin implements ArcanaPlugin {
    public String getId()           { return "io.github.you.foo"; }
    public String getName()         { return "Foo archive"; }
    public String getVersion()      { return "1.0.0"; }
    public String getSourceUrl()    { return "https://github.com/you/arcana-plugin-foo"; }
    public String getLicense()      { return "Apache-2.0"; }
    public String[] getExtensions() { return new String[] {"foo"}; }
    public boolean matches(byte[] header, String fileName) { return header.length >= 4 && header[0] == 'F' && header[1] == 'O' && header[2] == 'O' && header[3] == 0; }
    public ArchiveExtractor createExtractor(byte[] password) { return new FooExtractor(); }
}

      
In an extractor, always create files with PluginSupport.openOutput(destination, entryName): your plugin then gets the same path checks and extraction limits as the built-in formats.

    


    

      
Safety

      
An archive is data from someone else. Arcana treats it that way.

      

        
Paths

        
Entry names are cleaned before anything is written: no absolute path, no .., no character forbidden on Windows. An archive cannot write outside the destination directory.

        
Decompression bombs

        
The extracted size is compared to the archive size; extraction stops when the ratio becomes absurd. See extraction limits.

        
Disk space

        
Extraction stops before the disk is full.

        
Damaged data

        
Normal extraction stops at the first inconsistency and reports it; only arcana r keeps doubtful data, and labels it.

        
Executables

        
Arcana reads executables, it never runs them. The UPX plugin restores the original file without executing any of its code.

        
Plugins

        
A plugin must ship its source code, and arcana plugins shows the SHA-256 of each JAR so you know exactly which binary is loaded.

FAQ

      

        Do I need to install anything besides Java?
        
No. Arcana is a single JAR with no dependency and no native library. Java 8 or any later version is enough.

      

      

        Can Arcana create RAR archives?
        
No. RAR 4 and RAR 5 archives can be extracted, including encrypted and multi-volume ones, but not created. Use 7z or ZIP to create archives.

      

      

        A file has the wrong extension. Will Arcana still open it?
        
Yes for every format that has a signature: Arcana reads the content first. A ZIP renamed .dat or a Word document is opened as a ZIP. Only LZMA and Brotli streams, which have no signature, need their usual extension, or -f lzma / -f br.

      

      

        Extraction stops with "Error:" on a damaged archive. How do I get my files back?
        
Run arcana r on it. It extracts whatever can still be read and tells you, file by file, what is intact and what is not. See Damaged archives.

      

      

        What are the "[plugins]" lines printed before each command?
        
They report plugins that were found but refused, with the reason, or the fact that no plugin was found. They are printed on the error output, so they do not end up in a listing you redirect to a file. When every plugin loads correctly, nothing is printed.

      

      

        Can I use Arcana in a commercial product?
        
Arcana is under the Apache License 2.0, which allows it, including in closed-source software, provided you keep the license and copyright notices. Plugins have their own license: the UPX plugin, for example, is under the GPL-3.0-or-later. It is a separate JAR that you are free not to ship.

      

      

        Which Java versions are tested?
        
Every change is built and tested automatically with Java 8 and Java 21: compression and extraction round trips in every writable format, encrypted ZIP and 7z, and the loading of the official plugins.

      

    


    

      
Bugs and help

      
Arcana is young and may still contain bugs, especially with unusual archives. When something goes wrong, open an issue with the command line, the full error message, the Arcana version (arcana version) and, if you can share it, the file or a way to reproduce it.

      
Pull requests are welcome, and so are plugins: see Write a plugin.
